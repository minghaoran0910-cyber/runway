# DEV_WORKFLOW · 标准开发流程（v1.1）

> 核心 loop：**任务卡 → 开发 → 自检 → 审计 → 修改 → 测试 → 修改 → 验收**。
> 角色：浩然=决策；老油条=监工（审计/批准/合并把关，不写业务代码）；opencode=施工（按卡干活，永不自行合并）。

## 1. 任务卡（开工唯一凭据）
- 位置 `docs/tasks/SB-<nnn>-<slug>.md`（模板 `docs/tasks/TEMPLATE.md`）；无卡不写码，卡外功能一律拒绝（防 AI scope creep）。
- 必填字段：目标 / 涉及页面或模块 / 引用 DESIGN_SYSTEM 或 PRD 条款 / 验收标准（可测）/ 预估文件数（≤10）/ 依赖变更（默认无）/ 测试要求。
- 粒度：一张卡=一个可独立验收的用户可感知行为（如"三秒记一笔含分类选择"，不是"写数据层"）。

## 2. 施工规范（opencode 硬约束）
1. 每任务新会话，注入：本规范 + PRD + DESIGN_SYSTEM + 任务卡；禁止"喂全历史"。
2. 文件数 ≤10、单文件 ≤400 行；超了先拆卡。
3. 禁区（碰即打回）：`tokens.dart`、`pubspec.yaml` 新增依赖、数据 schema migration、README/规范文档、CI 配置。
4. 代码必须带测试：领域逻辑单测 / 每屏 golden / 交互 widget test。
5. 自检三件套提交前本地跑绿：`dart format` + `flutter analyze`（零 warning）+ 相关测试。
6. 不许 merge、不许 push main、不许 force push；提交只在 `feat/SB-nnn-slug` 分支。

## 3. 审计（监工，逐 PR）
checklist：范围=卡内？违反设计 token/动效规范？违反四层依赖方向？性能预算（启动/帧率/包体）受影响？隐私红线（通知原文零留存/本地加密）？测试真实有效（禁 assert-true 假测试）？数据库迁移可回滚？
产出判决：`通过` / `返工（列条）`；返工只列"违反哪条规范"，不口述改法（规范可执行是本项目第一资产）。

## 4. Loop 与升级
- 返工≤3 轮；第 3 轮未过=停下来改卡或改规范（可能是规范/架构问题，不硬磨）。
- 测试两层：自动（单测/golden/集成，CI 四闸门：format/analyze/test/build）+ 手动走查（监工在真机冒烟：Android 手机 + Mac 桌面，iOS/Win 在对应里程碑节点）。golden 与对比度闸门细则见 DESIGN_SYSTEM §2.3/§8，未跑绿不得进审计。
- 决策升级：凡涉及"范围/交互风格/命名/依赖/隐私"的疑问，汇总成决策点交浩然，一次一批。

## 5. 节奏与留痕
- 周一开工发周计划（本周卡列表），每日一句进展（干了啥/卡住啥/下一步），里程碑过闸门发演示说明。
- 每卡验收后归档到 `docs/tasks/done/`；CHANGELOG 随卡更新。
- 犯错必留痕：AI 产生的典型错误沉淀进 `docs/lessons.md`（如"同种按钮写出三种样式"类问题直接引用）。

## 6. 里程碑闸门（对齐 PRD 范围）
G0 规范批准 → G1 骨架（CI 全绿+token 落地）→ G2 核心闭环（记一笔/分类/目标看板）→ G3 钩子层（阶梯/成就卡/安全垫/周报）→ G4 采集（Android 通知监听/邮件导入）→ G5 打磨冻结（golden 全量走查+性能达标）→ tag v0.1.0。未过闸门不得预支下阶段功能。
