# ADR-iOS-通知采集路径（SB-024 纸面卡·Wave0·v2）

- 状态：Proposed（2026-10-12 v2；v1 作废。依据：浩然 16:57 裁定"改，这些其他平台也得同步做哈" + SB-024 第二轮修订令；待监工审计后转 Accepted）
- 范围：v0.2 Wave1 施工卡 V2-1 的前置定案。**纯调研文档，零代码，零依赖，零 schema 迁移。**
- 非目标：本 ADR 不施工、不改 `app/` 任何文件。PRD/ROADMAP 采集裁定已由监工 17:00 入册（`2e77dcf`），本文件只做设计侧展开，不重复改产品文档。
- v1 缺陷自申报：v1 正文含 2 处外语乱码残片（第 30/48 行）且首轮偏差声明误写"无偏差"，v2 已修复并如实申报（见文末偏差）。

## 0. 前提修正（路径被锁不等于通道被锁）

- 被锁死的是**主动拉**：iOS 第三方 App（支付宝/微信支付）的推送横幅对本 App 不可见、无订阅接口，非越狱设备上任何自称"监听全量通知自动记账"的方案都不成立（v1 前提保留）。
- 明文允许的是**被动推**：用户自建快捷指令自动化，把通知内容**推送式写入** App 沙盒文件，App 只做"读自家文件 + 解析"。此路不依赖"偷看"，苹果明文允许，与上条不矛盾。v1 把"无第三方推送触发器"过度推广为"快捷指令整条只能实验"，v2 纠正。
- 产品口径不变：任何平台不得宣传"全自动"，统一"待确认"（PRD §3）。

## 1. 对标基座（SB-010 Android 现状，复用点）

- 架构：`PendingListenerService`（系统通知使用权）→ 通道 `runway/notify_collector` → `app/lib/logic/notification_parse.dart`（纯 Dart，禁 import flutter）→ `pending_records`（schema v5）→ 待确认列表 → 一键入账走 SB-004 通道（`source='notify'`）。
- 去重键（SB-010 验收 4，d6ae1ab 定稿，废时间桶）：`makeNotifyKey` = `包名|tag|id|when毫秒|内容哈希`（SHA-1 hex，UTF-8，分隔符 `|`）；when 缺失/非毫秒可信（<1e12）回退 `包名|tag|id|内容哈希|postTime秒`。Dart 与 Android 双侧同口径，已知边界见卡 4b（when 系 App 自报，同秒两笔理论可并，人手不可达；通知重建出新 when 则多一条待确认，由待确认池消化）。
- 内容哈希：`notifyContentHash` = SHA-1(`包名|标题trim|金额分`)；标题原文只进哈希预镜像，不明文落库（PRD §5 原文零留存；pending 表无原文列，单测断言）。
- 采集目标包白名单：仅 `com.eg.android.AlipayGphone` / `com.tencent.mm`，余包丢弃；金额口径 `12.34元` / `￥12.34`（小数至多 2 位）。
- 产品约束继承：批量确认开关默认关（默认逐条确认）；"全自动"表述代码/文案零出现（grep 断言）。`insertPendingDedup` 入待确认池口径沿用。

## 2. iOS 路径重裁定（v2 推翻 v1 推荐方向）

### A · 快捷指令推送落盘（升正式渠道，主路径）

- 原理：用户建个人自动化（银行短信到达/每天固定时间/打开支付类 App 后），动作=把通知文本追加为一行 JSON 写入 App 沙盒文件；App 经 App Groups entitlement（`group.com.zangou.runway`）读该文件，解析后走同一 `notification_parse` + `insertPendingDedup` 入待确认池。快捷指令只做"搬运"，归类去重仍在 App 内（沿 SB-011 `docs/ios-shortcuts.md` 口径）。
- 与 v1 差异：v1 因"支付宝微信推送无触发器"把整条路判死刑；v2 改判——无触发器只影响"支付成功即时推"一种子情形，短信到账提醒/定时批量同步/开 App 后顺手推三种仍可达。覆盖率诚实口径：非全量实时，而是"半自动 + 待确认"，与 §0 一致。
- 限制：部分触发器需用户点确认（系统限制）；快捷指令写文件格式用户侧可改，App 侧容错（读失败整批跳过 + 当屏报错，不写盘）；用户删自动化或关确认则静默无数据，需空态引导"去检查快捷指令"，非崩溃。
- 工程量：M。iOS 侧加 App Groups entitlement + 共享容器读取器（Swift/Kotlin 对称实现写原生侧，Flutter 侧 Dart 解析复用 `notification_parse`）；待确认复用现有页；测试=单测（解析/去重）+ widget（待确认行）+ 真机建自动化端到端一次。预估文件 4–6（含测试）。
- 失败模式：共享容器被系统清理→读空按零条处理；多人共用 Apple ID 同步自动化→键冲突由 `notifyKey` 去重吞掉（安全方向：多出待确认，不丢账）。

### B · 邮件与文件导入（降级为对账兜底，不再是主力）

- 原理：沿 SB-011 链路——支付宝/微信导出账单文件（邮箱接收或本地保存）→ 分享进攒够 → 向导预览确认 → 去重（键=日期+金额+对方）→ 整批入账/可撤销本批。在线拉取以后再议（SB-011 卡文明示在线拉取留待以后迭代，v1 称 IMAP，v2 改称通用在线拉取，方向不变）。
- 定位：月/周粒度的补全对账，不承诺实时；在线拉取是否做，取决于体验期"账不全"到底有多痛，建议 Wave2 与"多账户"并案（v1 灰区口径保留）。
- 工程量：S（现状已可用，零新码即可用；iOS 侧无需 entitlement）。若加在线拉取则为 M（复用 `import_batch` + `pending`，新增取信器一个文件 + 授权页）。
- 失败模式：文件列格式随厂商改版漂移（SB-011 已有"失败行列号级报告"机制承接）；重复导入→去重键吞掉；授权撤销→降级为手动文件导入（与 SB-010"撤销后降级为手动"同构）。

### C · 手动补录兜底（SB-004 三秒记一笔，零新增，保留）

- 原理：不采集，靠现有三秒记一笔 + SB-005 分类引擎 + SB-019 角色轴兜底。首发期所有"采不到"的账都走这条。
- 限制：覆盖率靠用户自觉；"账全不全"（v0.2 主线"让账真"）在此路径下无客观保证，需 Wave1 用数据回答（体验期问题"账到底有多不全"正是 ROADMAP Wave2 的立项输入）。
- 工程量：0（已存在；本文档不列任何改动）。
- 失败模式：漏记（产品侧接受，沉淀在周报"预算之后接线行"等处以"无数据零高度"诚实表达，不编造）。

**v2 推荐：A 为正式主路径 + B 为对账兜底 + C 为永远兜底。**（推翻 v1 的"B 主力/A 附录"。）

## 3. 四平台四路导入矩阵（产品级能力，非 iOS 专属）

每格写法=路径 / 依赖 / 置信度 / 坑。每行一路由，每列一平台。

| 路 \ 平台 | iOS | Android | Mac | Windows |
|---|---|---|---|---|
| 通知捕获 | 快捷指令推送落盘 / App Groups 共享容器 + 待确认池 / 高 / 触发器无支付推送，需空态引导 | 原生监听服务 / 系统通知使用权 + `runway/notify_collector`（SB-010 已落地）/ 高 / 重建通知多出待确认，由池消化 | 目录监听 + 账单投递 / 落盘目录 + 同解析层 / 中 / 目录权限与文件占用冲突 | 目录监听 / 落盘目录即采集 + 同解析层 / 中 / 路径编码与长路径，VM 先行验证（W1 在跑） |
| 截图文字识别 | 系统离线识别 / 系统 Vision 本地 / 高 / 手写体与暗色模式阈值 | 系统离线识别或暂缓 / 复用统一解析层 / 中 / 机型差异，需抽样测 | 系统离线识别 / 系统 Vision 本地 / 高 / 多显示器截图路径 | 本地引擎选型 / PaddleOCR 与 Tesseract 对比，不联网 / 低 / 二选一需做 spike，包体与速度是坑 |
| PDF 账单 | 官方导出统一解析 / 四端同一解析层 / 高 / 厂商改版列漂移，走失败行报告 | 同左 / 同一解析层 / 高 / 同左 | 同左 / 同一解析层 / 高 / 同左 | 同左 / 同一解析层 / 高 / 同左 |
| 表格文件兜底 | 手动分享 + 加密压缩单独评估 / 分享通道 + `import_batch` / 中 / 微信加密压缩流程重，优先级最后 | 同左 / 同左 / 中 / 同左 | 同左 / 同左 / 中 / 同左 | 同左 / 同左 / 中 / 同左；邮件保留但不再称主力 |

- 统一约束：通知原文与账单文件**解析入库后即删盘**，只留结构化记录 + 哈希去重（沿 SB-010 原则；PRD 已入册）。
- 去重键分工不变：实时流（推送落盘/监听/目录）走 `makeNotifyKey`；批量流（文件导入）走 SB-011 键（日期+金额+对方）+ `import_batch` 整批撤销。两套键各管一行，不得发明第三套键（禁第二套公式，沿 SB-015/SB-017 先例）。
- `sourcePkg` 约定扩展：`ios-shortcut`（A 主路径）/ `ios-mail`（文件分享）/ 后续在线拉取走 `ios-imap`；Android 沿用 SB-010 值；Mac/Windows 目录路走 `desktop-dir`；C 走既有 `manual`。`confirmPending` 走 SB-004 通道逻辑不变。

## 4. schema 兼容面（明确结论，供 V2-1 直接引用）

- **零迁移**：复用 `pending_records`（schema v5，当前库 v11，`app_db.dart` 表定义在位），字段 `amountFen/occurredAt/category/merchant/sourcePkg/notifyKey` 已够四路用；**不新增列、不新增表**。
- 隐私红线继承：通知/邮件/文件原文零落库（只进哈希预镜像或读后即删）；"全自动"零表述；批量确认开关默认关。三条在 V2-1 验收中逐条断言，口径与 SB-010 验收 2/3 同构。
