# SB-010 · Android 通知监听采集（全量口径）

- **目标**：用户在系统设置授权"通知使用权"后，支付宝/微信等支付通知自动解析为**待确认**账单，一键入账。
- **引用条款**：PRD §3（采集口径：Android 通知监听（全量）；**任何平台不得宣传"全自动"**——产品文案统一"待确认"口径）、§5 隐私红线（**通知原文零留存**：解析后立即丢弃，仅存结构化字段）、§4（本地优先）；DEV_WORKFLOW §3 审计 checklist（隐私红线专项）。
- **授权声明**：本卡显式授权新增仓内平台插件 `packages/android_notification_collector/`（in-repo federated plugin，**禁止新增 pub 依赖**）；授权 schema v5 迁移（pending_records 表；可回滚）。
- **涉及模块**：`app/android/`（NotificationListenerService + 权限引导）、`packages/android_notification_collector/`（通道）、`app/lib/logic/`（解析规则接入 SB-005 引擎）、`app/lib/ui/`（待确认列表 + 一键入账）、`app/lib/data/`（pending DAO）。
- **验收标准**：
  1. 权限流：未授权→引导到系统设置；撤销后功能降级为手动，崩溃=打回
  2. 解析：支付宝/微信转账、消费通知样例 fixture（合成）→ 结构化待确认记录；**原文零落库**（单测断言 pending 表无 raw_text 列/值）
  3. 待确认列表：一键入账（走 SB-004 通道）、批量确认开关默认**关**（默认逐条确认，"全自动"表述在代码/文案中禁止出现，grep 断言）
  4. **去重按『通知对象身份』，不按时间桶**（2026-10-10 浩然毫秒思路，监工定稿）：同通知 key（包名|tag|id）+ 同 when（毫秒）+ 同内容哈希 → 判重复投递，吞；when 不同 → 即使同商户同金额同一分钟内两笔，各自入待确认，不吞。风暴场景（1 分钟 50 条合成）不丢不卡。when 缺失/非毫秒可信时回退 内容哈希+postTime(秒)。补单测 3 条：①同商户同金额不同 when → 保留 2 条 ②同通知重投(三同) → 仅 1 条 ③回退路径生效
  4b. 已知边界如实记（监工→产品决策留痕）：when 系 App 自报，同秒两笔理论可并（人手不可达）；通知重建出毫秒级新 when 的罕见情形多出一条待确认，由待确认池一键消化，非静默错账
  5. 监工在 Android 真机冒烟（DEV_WORKFLOW §5 手动走查）；四闸门全绿 + hygiene OK
