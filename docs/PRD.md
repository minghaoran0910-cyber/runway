# PRD · 产品定义与架构（v1.1）

> **定位修正（10-08 晚，以此为准）**：本项目目标不是商业化上架，而是**按商业应用市场级品质标准做的自用旗舰产品**；发布与否为后置决策。飞书《商业化 MRD v2.0》中"立项/发布/止损"表述均按本修正执行，品质要求不变。完整论证见飞书（Sl1XdWcENoShfwxLMSfcgyRFnIc）；本文件只提取执行所需的产品决策与架构约束，两处冲突时以飞书评审后的最新版为准。

## 1. 一句话定义

**把每天省下的钱，攒成具体想要的东西和离开的底气。** 记账是手段，"攒出 iPhone、攒出安全感"才是产品。

## 2. 产品主线（三层价值阶梯）

| 层 | 内容 | 交付形态 |
|---|---|---|
| 看见 | 极速记一笔（≤3 秒）+ 自动归类 + 30 秒日报 | 每日 |
| 攒到 | 目标阶梯：奶茶→5090→余粮→自由基金→FIRE；实物换算 + 成就卡 | 周/月 |
| 改变 | 自动预算 + 大额冷静期 + 月度实验 | 月 |

## 3. 范围硬边界

- 资产/投资：**只记录、只展示，永不输出买卖建议**（净资产快照：手动录入 + 每日市值更新）。
- 采集口径：Android 通知监听（全量）；iOS 快捷指令半自动 + 邮件账单导入 + 手动兜底。**任何平台都不得宣传"全自动"**。
- 类目失败态："其他"金额占比 >5% 视为分类系统故障，列入迭代修复任务。
- 非目标：投资建议、资金通道、社区、广告、云端同步（加密方案评审通过前）。

## 4. 技术架构（约束条款）

- **框架：Flutter（单码四端 iOS/Android/Win/Mac）✅ G0 已批准（2026-10-09），本条为硬约束**。理由：渲染一致才能"同一套设计语言跨平台"；动效（Impeller/spring）与 Golden 测试是一等公民；Dart 静态类型利于 AI 协作可审。批准后禁止任何"某端用原生重写"的提案（除非性能预算证明 Flutter 不可达，走 ADR）。
- 分层：`ui / logic / data / infra` 四层单向依赖；领域模型不依赖 Flutter 类型。
- **本地优先**：SQLite（drift，SQLCipher 加密），离线全功能；云同步仅预留接口，不实现。
- 通知采集：Android `NotificationListenerService`，**解析后立即丢弃原文，仅保留（金额/商户/时间/账户提示）结构化字段**；处理 OEM 保活（电池优化白名单引导页）。
- 数据模型基线：`transaction(amount, merchant, time, accountId, typeAxis[消费|资金流动|收入], natureAxis[固定|必要|弹性], goalLink?)`；goal(`name, targetAmount, unitPrice, tier, doneAt`)；账户与快照。迁移一律用 drift migration，禁止手改 schema。
- 性能预算（硬闸门）：冷启动 <1.5s（中端机）；动画 60fps 保底、120Hz 适配；App 包体 <30MB。

## 5. 隐私与安全红线

- 本地加密存储；不申请通讯录/相册/定位；不接任何第三方统计或广告 SDK。
- 支付通知原文零留存、零上云；导出功能默认 CSV 本地导出。
- 密钥/口令不写日志、不入库、不进 git。

## 6. 指标（自证品质，非 KPI 竞赛）

D7 留存、三秒记账实测、"其他"占比、周报互动率、目标达成数/自设目标总数（个人产品口径，不做用户间对比）。
